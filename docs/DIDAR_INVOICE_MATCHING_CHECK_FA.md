# بررسی خواندن فاکتور دیدار برای تطبیق با سپیدار

تاریخ: ۱۴۰۵/۰۸/۰۴ (۲۰۲۶/۱۰/۲۶)

با اجازه صریح کاربر در گفتگو، فقط شماره سه فاکتور فروش موجود در snapshot سپیدار به API رسمی دیدار ارسال شد. هیچ سندی ایجاد، ویرایش یا حذف نشد؛ هیچ مجوزی تغییر نکرد. کلید، شماره واقعی فاکتورها و اطلاعات مشتریان در این گزارش ذخیره نشده‌اند.

| آزمون | نتیجه |
|---|---|
| دریافت کاریزها با کلید فعلی | موفق؛ ۴ کاریز |
| دریافت فاکتور نمونه اول | HTTP 401 |
| دریافت فاکتور نمونه دوم | HTTP 401 |
| دریافت فاکتور نمونه سوم | HTTP 401 |

درخواست مطابق مستندات: POST به `https://app.didar.me/api/AccountingInvoice/Get`، کلید در پارامتر `apikey` و یک فیلد `InvoiceNumber` در بدنه JSON؛ شماره با قالب رشته اعشاری نمونه مستندات ارسال شد. پاسخ‌های ۴۰۱ پیام JSON توضیحی نداشتند.

نتیجه: اعتبار کلید برای دست‌کم API کاریزها تأیید شد. دسترسی به API دریافت فاکتور با همان کلید موفق نشد. وجود یا نبودن سه سند در دیدار، شناسه مشترک ردیف‌های سپیدار و دیدار، و نرخ موفقیت تطبیق هنوز قابل تأیید نیستند. ۴۰۱ به معنای پیدا نشدن فاکتور نیست. علت دقیق می‌تواند به دسترسی کلید، حساب یا نحوه پشتیبانی این endpoint مربوط باشد و از پاسخ فعلی تعیین نمی‌شود.

طبق مستندات، پاسخ فاکتور دارای شماره، تاریخ، وضعیت ابطال، شناسه معامله، مشخصات خریدار، مبالغ، اقلام و `Items[].ThirdPartyInvoiceItemId` است. این فیلد تنها در صورتی اتصال قطعی به سپیدار می‌سازد که واقعاً با شناسه ردیف سپیدار پر شده باشد؛ مقدار آن روی حساب واقعی هنوز خوانده نشده است.

متن مناسب برای مدیر حساب/پشتیبانی دیدار:

> با API Key فعلی، `/api/pipeline/list/0` پاسخ موفق می‌دهد، اما `/api/AccountingInvoice/Get` برای درخواست مطابق مستندات و با فقط InvoiceNumber، پاسخ 401 بدون پیام JSON می‌دهد. لطفاً بررسی کنید خواندن فاکتور از Open API برای این حساب و کلید پشتیبانی و مجاز است یا نیاز به تنظیم دیگری دارد. کلید را در پاسخ عمومی ارسال نمی‌کنیم.

منابع: [دریافت فاکتور](https://developers.didar.me/Get-Invoice-Quote)، [ایجاد فاکتور و فیلدها](https://developers.didar.me/Create-Invoice).
